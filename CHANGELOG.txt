ESPHome Toshiba A2A development
===============================

Sep 16th 2026

* refactor branch review cleanup: repaired generated profile/identity headers, removed E0-driven FIX registration/write gates, made FIX selects normal ESPHome entities governed by the explicit installation capability profile, and removed the obsolete Power Select cancellation path so functional code follows the current interaction policy
* branch refactor: renamed the ESPHome component/namespace from inherited `toshiba_suzumi` to `toshiba_a2a`, separated E0 identity decoding from declarative device-profile data, and routed proven A3 family differences through a louvre-encoding profile rather than direct family checks in control code
* separated ordinary A3 swing readback from FIX-selector readback on the validated path: ordinary Off/Vertical/Horizontal/Both states now remain climate swing state only, while packed P2 FIX values continue to update the fixed-position selectors; this removes invalid `Off`/`Swing` publications into FIX-only selects without adding any OFF-state write restriction yet
* replaced E0-driven FIX exposure with an explicit optional package `capability_profile`: `full` is the default and exposes the expected family FIX controls, while `limited` hides firmware-variable FIX controls; the known older Office B10J2 example now opts into `limited`, and P2 vertical/horizontal FIX are restored to Home Assistant through stable package-level wrapper selects
* added TOSHIBA_CONTROL_INTERACTION_RULES.md as the distinct shared control-policy resource: ordinary special functions are mutually exclusive, Power Select is normally independent, Silent 1/2 override both Power Select and the active special function, PURE remains independent, and heat-only functions in Auto are valid only while the unit is actually heating
* validated boot-time J2 FIX exposure on the older Office B10J2: with no usable persisted E0 IDU model the FIX selector remained hidden from Home Assistant, while ordinary J2 swing 31/41 and Quiet fan operation continued to work normally
* changed J2 FIX exposure to a boot-time decision using the persisted Toshiba-reported E0 IDU model: no learned model keeps the public FIX selector internal/hidden, while a previously learned valid model exposes it; first-time discovery therefore requires one reboot/install on ESPHome 2026.8.x
* fixed ESPHome fan-mode exposure/readback so Auto / Quiet / Low / Medium / High use native climate fan modes while only Toshiba's intermediate levels 2 and 4 use custom fan modes; this restores working Quiet control (`A0/F8 = 31`) and keeps readback consistent with Home Assistant traits
* changed J2 FIX to passive state handling: the Home Assistant selector now contains only Top / Upper / Centre / Lower / Bottom, has no 1-second template polling, and updates only when the IDU reports A3 50..54
* separated ordinary J2 A3 swing readback from FIX readback so Off/Vertical states no longer get published into the fixed-position selector; FIX writes are rejected until a usable Toshiba-reported E0 IDU model is known
* directly verified the full B13J2 FIX sequence while running: A3 50 Top, 51 Upper, 52 Centre, 53 Lower, 54 Bottom; a FIX write while the unit was off was ACKed but ordinary A3 Off remained the reported state until operation resumed
* simplified README.md to a short project overview, tested-hardware summary, installation pointer, safety note and attribution; moved current implementation detail and limitations to current_status.md
* returned Focused Monitor to passive operation: it no longer injects A3/A4 reads or other monitor-generated UART requests
* added an unconditional decoded E0 equipment-packet log so repeated identity can be distinguished from no E0 traffic
* treated E4 +2 FE/FF as unavailable fan-speed feedback instead of numeric speed
* confirmed the long Wi-Fi->IDU 0x99 onboarding frame contains clock/calendar synchronisation fields
* made the exact IDU model mandatory in package consumers for family/protocol routing while keeping E0 as the Toshiba-reported runtime identity source
* separated J2FVG and P2KVSG A3 control encoding: J2 FIX uses 50..54 and J2 vertical swing uses 31/41; P2 retains its packed H/V FIX representation
* integrated reusable J2 and P2 package templates into main and added package compile CI
* rewrote the user-facing control matrix around the directly tested J2FVG and P2KVSG families

Sep 15th 2026

* confirmed J2FVG ON/OFF timer duration and enable registers (92/90 and 96/94), including autonomous ON-timer expiry behaviour
* directly mapped B13J2FVG vertical FIX commands from genuine-adaptor captures: 50, 51, 52, 53, 54
* independently reproduced the complete F8 fan-command enum on B13J2FVG: Quiet 31, levels 1-5 32..36, Auto 41
* confirmed the four-byte F8 structure as mode / target / fan / function across directly captured J2FVG and P2KVSG traffic

Sep 14th 2026

* added J2FVG family-specific capability and mode profiles instead of inheriting a broad generic residential profile
* documented Toshiba J2 control semantics and separated documented behaviour, direct observations and unresolved multi-split interactions
* decoded pushed E0 equipment identification into IDU and ODU records and exposed model/identity fields
* decoded P2 A3 FIX as a packed horizontal/vertical `A3` representation. Vertical and horizontal state are therefore handled differently from J2 and remain in the P2 package.
* added the validated P2 control layer with separate Home Assistant entities for Power Select, ECO, Hi POWER, Silent Operation, PURE, 8 °C Heat and defrost
* implemented directly observed P2 mode restrictions and Power Select cancellation behaviour
* promoted E4 +2 to live IDU fan-speed feedback on the tested units and updated model-specific airflow estimation accordingly

Sep 13th 2026

* split family-level control capability mapping from exact-model airflow/performance data
* replaced large manual airflow lookup tables with compact model-specific interpolation ranges
* expanded TOSHIBA_REGISTER_MAP.md into the evidence-graded protocol reference
* validated major F8 control traffic, timer behaviour, filter/service-time data and energy-monitoring transfer families

Sep 11th 2026

* established insipiens/esphome-Toshiba-A2A as an independent GPLv3 repository derived from pedobry/esphome_toshiba_suzumi
* retained explicit provenance and upstream acknowledgements
* introduced E0 model identification, family capability groundwork and the move away from one monolithic climate-preset abstraction
* separated normal installation examples from diagnostic, engineering and output-estimation research examples

Jul-Aug 2026 development carried into this repository

* replaced the earlier scanner with passive/raw diagnostic capture and controlled investigation tooling
* standardised IDU/ODU terminology
* extended E4/E5 engineering telemetry handling and began calibration against independent measurements
* added the experimental IDU sensible-output estimator

Detailed register-level findings and evidence history are maintained in TOSHIBA_REGISTER_MAP.md and current implementation status in current_status.md.
