ESPHome Toshiba A2A development
===============================

Sep 19th 2026

* directly reproduced the OFF-timer command path from the ESP controller while the IDU was running: `0x96 = 00 1E` (30 minutes) and `0x94 = 0x41` were both ACKed and the unit continued operating with live fan feedback after arming; expiry was not included in the capture
* confirmed that the IDU accepts and arms a non-remote ON-timer duration: `0x92 = 0A 1E` (10 h 30 min) received the normal ACK, `0x90 = 0x41` was ACKed, and `0x80 = 0x30` followed while airflow remained zero; expiry at 10 h 30 min remains untested
* changed ON/OFF timer availability gating from cached `0x80` power state to the climate operating state, because `0x80` can report logical/armed ON while an ON timer is waiting and the IDU is still physically stopped
* directly reproduced a 30-minute ON timer from the ESP controller: `0x92 00 1E` and `0x90 41` were ACKed, `0x90` read back active, and the IDU reported the expected armed `0x80 = 0x30` state while airflow remained zero
* handled validated `0x90`/`0x94` timer-state readback entirely in the timer layer so confirmed ON/OFF timer states no longer fall through to the legacy parser as spurious `Unknown sensor: 144/148` warnings
* exposed separate `ON Timer` and `OFF Timer` Home Assistant selects using the validated `0x92/0x90` and `0x96/0x94` timer paths; both cover 30 minutes through 12 hours in 30-minute steps; ON Timer accepts new durations only while the unit is OFF and OFF Timer only while the unit is ON, while `Off` remains available in either state for cancellation
* replaced the speculative J2 `F7` Comfort control with a falsifiable Comfort Sleep duration selector (`Off`, `1 hour`, `3 hours`, `5 hours`, `9 hours`): activation reproduces the directly observed remote-control result by selecting 50% Power Select, Auto fan, programming the established `0x96` OFF-timer duration and enabling `0x94`; cancellation disables the OFF timer; added generic multi-byte register-write support for the two-byte timer duration

Sep 18th 2026

* corrected the common Toshiba RX framer to honour the full 16-bit big-endian protocol length in bytes 5-6 instead of the low byte only; this allows long genuine Toshiba frames such as CC/CE/CF energy-history responses to reach the normal parser and Focused Monitor intact; Focused Monitor now chunks long frames for readable lossless logging, and CI checks representative 15-, 358-, 502- and 890-byte frame lengths
* culled obsolete development fixtures and the branch-only refactor workflow; reduced public examples to the universal installation template and passive sniffer; consolidated control interaction policy into the control matrix; salvaged the advanced genuine-adaptor frame reassembly from the sniffer branch into a reusable example helper; removed the obsolete ESP-IDF CPU-frequency override
* removed the obsolete J2 manual-summary document and its references; user documentation now avoids reproducing or paraphrasing Toshiba reference material, while engineering values retain concise provenance as derived from published datasheets, direct measurement or protocol observation
* overhauled the user documentation with separate installation, usage/options, hardware assembly, passive-sniffer and new-model contribution guides; added the corrected PCB Gerbers and a populated working-board photograph, documented the tested Tencent ESP32-C3 SuperMini/CYT1076/JST BOM, clarified the distinction between Focused Monitor and a two-channel receive-only sniffer, refreshed every example and expanded CI to compile all examples
* integrated the model-specific sensible-output estimator into the universal package: supported models now expose IDU airflow plus estimated heating and cooling output automatically; unsupported models or unresolved airflow remain unavailable instead of using a generic estimate; a restored 0.00–1.00 `IDU Output Multiplier` permits runtime calibration of both output estimates; the standalone output example now uses a non-conflicting climate ID on current ESPHome
* prepared the tested protocol/model refactor for promotion to `main`: the universal package and reference examples now track `main` rather than the temporary refactor branch
* restored `climate_entity_name` as a separate optional installation substitution for the climate entity name, while retaining `device_name` for ESPHome/network identity, `friendly_name` for the Home Assistant device name and `toshiba_model` for family/profile selection; `climate_entity_name: ""` is supported for users who prefer composed naming
* simplified Focused Monitor into a raw UART recorder: logs TX/RX direction, hexadecimal register address when structurally identifiable, frame length and raw bytes; retains simple request/response correlation but removes payload/state interpretation and speculative remote-origin labelling; timeout, checksum-failed and invalid-header RX traffic is now logged instead of silently discarded
* corrected family capability evidence: J2 does not advertise PURE, retains Comfort Sleep as a distinct non-timer function, and exposes Start/Strong Defrost independently in Heat; P2 no longer advertises unproven Fireplace/Sleep/Comfort capabilities; the `defrost` installation override masks both defrost actions
* made family capabilities the single authority for whether a function exists; per-mode function lists now only restrict those family features by HVAC mode, with compile-time assertions that every mode feature is present in the family capability mask
* replaced family-specific user packages with one universal `packages/toshiba-a2a.yaml`: users provide `device_name`, `friendly_name` and `toshiba_model`; the component resolves family/capabilities internally, while optional `disable_features` masks individual controls such as `fixed_position` for older/reduced IDU controllers
* upgraded Focused Monitor to loitering transaction-aware diagnostics: it observes normal board TX and IDU RX, correlates request/response traffic, logs unsolicited/passive publications and highlights changed unsolicited registers as remote/control-origin candidates without injecting exploratory reads
* removed the obsolete `special_mode:` schema and the remaining legacy unvalidated special-mode/power-select entity classes; all exposed dedicated controls now use the validated profile-aware path

Sep 17th 2026

* completed protocol/model separation checkpoint: common physical registers and wire values now live in `toshiba_registers.h`; J2FVG/P2KVSG capabilities and A3 encodings live in declarative family headers; the controller retains one resolved family profile; configured special-function controls use the profile-aware path; and obsolete self-modifying refactor tooling was removed
* refactor branch hardware-test packages now point their external component source at `refactor/toshiba-protocol-model-separation` rather than `main`, ensuring J2/P2 test flashes actually build the refactored `toshiba_a2a` code

Sep 16th 2026

* refactor branch review cleanup: repaired generated profile/identity headers, removed E0-driven FIX registration/write gates, made FIX selects normal ESPHome entities governed by the explicit installation capability profile, and removed the obsolete Power Select cancellation path so functional code follows the current interaction policy
* branch refactor: renamed the ESPHome component/namespace from inherited `toshiba_suzumi` to `toshiba_a2a`, separated E0 identity decoding from declarative device-profile data, and routed proven A3 family differences through a louvre-encoding profile rather than direct family checks in control code
* separated ordinary A3 swing readback from FIX-selector readback on the validated path: ordinary Off/Vertical/Horizontal/Both states now remain climate swing state only, while packed P2 FIX values continue to update the fixed-position selectors; this removes invalid `Off`/`Swing` publications into FIX-only selects without adding any OFF-state write restriction yet
* replaced E0-driven FIX exposure with an explicit optional package `capability_profile`: `full` is the default and exposes the expected family FIX controls, while `limited` hides firmware-variable FIX controls; the known older Office B10J2 example now opts into `limited`, and P2 vertical/horizontal FIX are restored to Home Assistant through stable package-level wrapper selects
* added TOSHIBA_CONTROL_INTERACTION_RULES.md as the distinct shared control-policy resource: ordinary special functions are mutually exclusive, Power Select is normally independent, Silent 1/2 override both Power Select and the active special function, PURE remains independent, and heat-only functions in Auto are valid only while the unit is actually heating
* validated boot-time J2 FIX exposure on the older Office B10J2: with no usable persisted E0 IDU model the FIX selector remained hidden from Home Assistant, while ordinary J2 swing 31/41 and Quiet fan operation continued to work normally
* changed J2 FIX exposure to a boot-time decision using the persisted Toshiba-reported E0 IDU model: no learned model keeps the public FIX selector internal/hidden, while a previously learned valid model exposes it; first-time discovery therefore requires one reboot/install on ESPHome 2026.8.x
* fixed ESPHome fan-mode exposure/readback so Auto / Quiet / Low / Medium / High use native climate fan modes while only Toshiba's intermediate levels 2 and 4 use custom fan modes; this restores working Quiet control (`A0/F8 = 31`) and keeps readback consistent with Home Assistant traits
* changed J2 FIX to passive state handling: the Home Assistant selector now contains only Top / Upper / Centre / Lower / Bottom, has no 1-second template polling, and updates only when the IDU reports A3 50..54
* separated ordinary J2 A3 swing readback from FIX readback so Off/Vertical states no longer get published into the fixed-position selector; FIX writes are rejected until a usable Toshiba-reported E0 IDU model is known
* directly verified the full B13J2 FIX sequence while running: A3 50 Top, 51 Upper, 52 Centre, 53 Lower, 54 Bottom; a FIX write while the unit was off was ACKed but ordinary A3 Off remained the reported state until operation resumed
* simplified README.md to a short project overview, tested-hardware summary, installation pointer, safety note and attribution; moved current implementation detail and limitations to current_status.md
* returned Focused Monitor to passive operation: it no longer injects A3/A4 reads or other monitor-generated UART requests
* added an unconditional decoded E0 equipment-packet log so repeated identity can be distinguished from no E0 traffic
* treated E4 +2 FE/FF as unavailable fan-speed feedback instead of numeric speed
* confirmed the long Wi-Fi->IDU 0x99 onboarding frame contains clock/calendar synchronisation fields
* made the exact IDU model mandatory in package consumers for family/protocol routing while keeping E0 as the Toshiba-reported runtime identity source
* separated J2FVG and P2KVSG A3 control encoding: J2 FIX uses 50..54 and J2 vertical swing uses 31/41; P2 retains its packed H/V FIX representation
* integrated reusable J2 and P2 package templates into main and added package compile CI
* rewrote the user-facing control matrix around the directly tested J2FVG and P2KVSG families
