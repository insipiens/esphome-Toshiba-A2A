ESPHome Toshiba A2A development
===============================

Sep 13th 2026

* split model handling into two lightweight runtime matrices: family-level control capabilities and exact-model airflow/performance ranges
* made family capability mapping explicitly table-driven so capacity variants share the same control/function profile
* replaced the large per-W-level/per-manual-level airflow lookup with compact exact-model cooling/heating endpoint ranges containing minimum/maximum fan feedback and minimum/maximum air volume
* changed live airflow estimation to linear interpolation across those model-specific endpoints; values outside the known feedback range are deliberately not clamped so previously unseen fan speeds remain detectable
* retained a lightweight five-step manual-fan fallback for IDU firmware that does not expose usable live fan feedback
* expanded the UART register map from tentative observations into an evidence-graded protocol reference, separating confirmed sniffer observations from draft/provisional interpretations
* validated aggregate F8 control traffic and documented command/state behaviour observed through the Toshiba Wi-Fi adaptor
* mapped horizontal louvre FIX positions from ordered app tests; observed values 0x85, 0x8D, 0x95, 0x9D, 0xA5 and 0xAD correspond to six ordered positions, with the third position being straight ahead; degree-like encoding remains an interpretation
* validated Hi Power switching through Wi-Fi sniffer traffic and retained feature-state semantics separately from the aggregate F8 command
* validated ON-timer and OFF-timer command behaviour, including mirrored duration encoding; documented that the app exposes ON timer only while the unit is off and OFF timer only while the unit is on, while noting this restriction may be app-side logic
* captured a complete ON-timer expiry sequence: the IDU unsolicited state push changes 0x90 to 0x42 at expiry and E4 subsequently shows fan activity; the wider logical-state interpretation remains explicitly DRAFT/provisional
* confirmed CA as filter/service-time information: configured filter interval is returned in hours, including observed 1000 h (0x03E8) and 500 h (0x01F4) settings
* documented CC-CD-CE-CF energy-monitoring/dashboard transfers and their large structured payloads; IDU versus system-wide field locality remains unresolved until multiple Wi-Fi-connected IDUs can be compared
* recorded observed Toshiba app energy totals (hour/day/month context) as correlation targets for decoding the energy-monitoring payloads
* improved documentation of register frame lengths, payload sections, request/response direction and validation status rather than treating registers as simple scalar values
* retained unresolved fields and interpretations as draft/probable instead of promoting correlations to confirmed protocol semantics

Sep 11th 2026

* established independent `insipiens/esphome-Toshiba-A2A` repository from the substantially modified `esphome_toshiba_suzumi` codebase
* retained GPLv3 licensing and explicit provenance/attribution to the upstream project and its referenced prior work
* documented the project's deliberately limited direct test population and evidence-driven reverse-engineering method
* added E0 equipment-identification decoding and IDU/ODU model entities
* introduced model/family capability groundwork
* began replacing the legacy F7 climate-preset abstraction with separate Toshiba-specific Home Assistant controls
* documented a model x HVAC-mode x control capability/dependency matrix as the next validation stage
* separated passive UART capture, engineering telemetry and experimental output-estimation examples from the normal installation example
* removed the ESP8266 example because this project has not tested ESP8266

Jul-Aug 2026 development carried into this repository

* replaced the earlier one-shot register scanner with passive/raw diagnostic capture and controlled register-investigation tooling
* added focused header/raw/decoded logging and clean stop/resume behaviour
* renamed diagnostic YAML options and internal identifiers to consistent IDU/ODU terminology
* renamed inherited `cdu_*` / `fcu_*` diagnostic keys to descriptive `odu_*` / `idu_*` names
* added/extended E4 IDU and E5 ODU/system telemetry handling
* calibrated the current-like E5 value against independent electrical metering; exact locality/system semantics remain under investigation
* corrected the interpretation of the IDU fan field: it is not claimed to be literal RPM
* added an empirical IDU sensible-output estimator calibrated from the B13J2FVG reference unit; this remains experimental and is not a generic Toshiba COP model
